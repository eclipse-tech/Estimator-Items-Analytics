# City Canonical Mapping - How It Works

## Problem
The original script was creating separate entries for typo variations instead of grouping them:
- `"Bangalore": ["bangalore"]` ❌
- `"bangalor": ["bangalor"]` ❌  
- `"bengaluru": ["bengaluru"]` ❌

## Solution
We now **merge database cities with manually curated typo variations**:
- `"Bangalore": ["bangalore", "bengaluru", "bangalor", "banglore", ...]` ✅

## How It Works

### 1. Manual Typo File (`city_typos_manual.json`)
Contains curated typo variations for major cities:
```json
{
  "Bangalore": [
    "bangalore", "bengaluru", "bengalore", "banglore", 
    "banglor", "bang", "blr", "blore", ...
  ],
  "Hyderabad": [
    "hyderabad", "hydrabad", "hyd", "hyder", ...
  ]
}
```

### 2. Database Cities
The script fetches actual city names from your database:
- "Bangalore"
- "Bangalore Sarjapur"
- "Bengaluru"
- "Mumbai"
- etc.

### 3. Merging Process

#### Step 1: Load Manual Typos
```
Manual typos loaded with pre-defined variants for major cities
```

#### Step 2: Process Each Database City
For each city from the database:

**Example 1: "Bangalore Sarjapur"**
1. Normalize: `"bangalore sarjapur"`
2. Try exact match against typo variants: ❌ No match
3. Extract first word: `"bangalore"`
4. Try first word match: ✅ Matches "bangalore" in Bangalore's variants
5. **Result**: Add `"bangalore sarjapur"` to Bangalore's variants

**Example 2: "Bengaluru"**
1. Normalize: `"bengaluru"`
2. Try exact match: ✅ Matches "bengaluru" in Bangalore's variants
3. **Result**: Already in Bangalore's variants (no duplicate added)

**Example 3: "Patna"** (not in manual typos)
1. Normalize: `"patna"`
2. Try exact match: ❌ No match
3. Try first word match: ❌ No match
4. **Result**: Create new entry `"Patna": ["patna"]`

### 4. Final Output (`city_canonical_mapping.json`)
```json
{
  "Bangalore": [
    "bang",
    "bangalore",
    "bangalore sarjapur",
    "bangalore sonailhalli",
    "bangalor",
    "bangaloru",
    "bengaluru",
    "bengalore",
    "benglore",
    "blr",
    "blore",
    ...
  ],
  "Hyderabad": [
    "hyd",
    "hyder",
    "hyderabad",
    "hydrabad",
    ...
  ],
  "Patna": ["patna"]
}
```

## Key Features

### ✅ Groups Similar Cities
- "Bangalore", "Bengaluru", "Bangalore Sarjapur" → all under "Bangalore"
- Handles multi-word cities (e.g., "Bangalore Sarjapur")

### ✅ Preserves Manual Typos
- Keeps all manually curated typo variations
- Adds database variants to existing canonical cities

### ✅ Handles New Cities
- Creates new entries for cities not in manual typos
- Uses proper case as canonical name

### ✅ No Duplicates
- Each variant appears only once per canonical city
- Sorted alphabetically for consistency

## Files

### Input Files
1. **`city_typos_manual.json`** - Manually curated typo variations
   - Location: `backend/resources/`
   - Edit this file to add/update typo variations for major cities

2. **Database** - Live city data from finalized estimators
   - Fetched automatically by the script

### Output Files
1. **`city_canonical_mapping.json`** - Final merged mapping
   - Generated by `fetch_cities.py`
   - Used by the application for city name matching

2. **`city.csv`** - List of all unique cities
   - Simple CSV with one column

## Usage

### Running the Script
```bash
# Inside backend folder
python scripts/fetch_cities.py

# Or via Docker (runs automatically on container startup)
docker-compose up backend
```

### Adding New Typo Variations
1. Edit `backend/resources/city_typos_manual.json`
2. Add variants to the appropriate canonical city:
```json
{
  "Bangalore": [
    "bangalore",
    "your-new-typo-here"
  ]
}
```
3. Run the script to regenerate `city_canonical_mapping.json`
